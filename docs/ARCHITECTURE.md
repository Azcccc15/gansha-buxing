# 系统设计说明

干啥不行目标规划管理软件 V1.0 包含共用界面、安卓适配层和可选的电脑开发服务。

## 规划与记录

新目标校验后请求 DeepSeek，返回 ready、needs_information、cannot_plan。ready 仅为草案，用户确认后才写入本机记录。问卷最多三题、一轮完成，提交原题和是非答案以支持无状态分析。完成记录与目标达成独立处理，不按任务计数自动宣布成功。

目标保存原文、开始日期、周期、阶段、成果标准、行动、达成及结束状态。行动保存独立编号、目标内天数、本地日期、时间、时长、完成标准、完成时间和删除状态。没有撤销完成的业务操作。后续规划使用剩余周期，确认后偏移并追加，不覆盖既有完成历史。

## 本机存储

目标使用版本化 JSON 保存。变更先在副本执行，写入成功后再更新页面；写入失败保留原状态。读取异常阻止覆盖并提供原始记录导出。监听浏览器存储变化并拒绝发现的过期状态写入。本机资料不是防设备管理员篡改的账本。

手机密钥使用 Keystore 的 AES 密钥进行 AES-GCM 加密，旧密钥不回传 JavaScript。禁用云备份和设备转移的应用数据，个人导出由用户主动选择。发布签名不进入仓库，与用户 AI 密钥分别保存。

## 安卓系统适配

WebView 只加载本包白名单资源，以独立 HTTPS 本地域名作为来源。禁止外部导航、页面网络连接、混合内容和任意文件访问。原生桥限制固定路径，响应经过 JSON 编码；正式包关闭网页调试。

系统 HTTPS 固定连接 DeepSeek，禁止重定向，限制超时和响应大小，校验周期、预算、阶段连续覆盖、任务日期及问卷结构。错误不回显密钥、上游正文或模型思考。服务端和手机端各自执行校验。

提醒保存未到期行动集合，使用非精确 AlarmManager 和通知渠道，完成、删除和结束目标时同步取消。重启、应用替换或时区变化后重排。接收器检查预期系统动作。日历通过 ACTION_INSERT，导出通过 ACTION_CREATE_DOCUMENT，不申请读取现有日历或全盘文件权限。

## 电脑服务与构建

Node 服务默认仅本机监听。开放网络前需要访问口令，规划入口有大小、来源、频率、并发和超时限制。本机密钥设置检查 Host、Origin、设置令牌，成功落盘后才更换运行凭据。

安卓使用 Java 17、Gradle 8.11.1、Android Gradle Plugin 8.9.3 和 SDK 35。构建从共用目录同步界面和提示词。Node 检查验证接口及记录规则，浏览器检查覆盖问卷、确认、持久化、删除与成就。Android Lint、签名校验和设备验收分别记录，静态检查不代替设备运行结果。
